# 设计原则

KKDUI 不追求覆盖所有页面类型，而是把后台管理中反复出现的交互约定沉淀下来。

## 业务状态保持受控

筛选、弹层和导航状态使用 Vue `v-model`，请求、缓存与权限仍由业务层控制。组件负责交互，不接管业务数据。

## 信息密度服务于任务

后台界面需要同时展示更多信息，但密度不等于拥挤。组件通过清晰层级、稳定间距和可预测的状态反馈减少误操作。

## 危险操作必须明确

删除、封禁、配置发布等操作应提供风险说明、二次确认和处理中状态，避免将不可逆操作伪装成普通按钮。

## 可访问性是默认能力

键盘导航、焦点环、语义属性、减少动画偏好和移动端触控尺寸应在组件内部得到一致处理，而不是留给每个业务页面重复补充。

## 保持核心轻量

核心组件只依赖 Vue。图表、富文本等重量级能力由业务项目按需选择，KKDUI 不把第三方运行时强加给所有使用者。
